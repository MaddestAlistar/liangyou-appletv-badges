# V9 核查 · 2026-09-25

## 用户截图能确认什么

截图中可见 REMUX 与 UHD Blu-ray 同时出现，也可见 DV P7 + Atmos / TrueHD、通用 DV + Atmos / TrueHD 和独立 TrueHD 并列。它说明最终界面没有完成预期的全局去重。仅凭截图无法确定实际参与匹配的所有字符串，或客户端是否同时保留了旧规则。

V8 的单字符串测试覆盖不足以保证这种界面行为。按多个独立字段分别匹配、再汇总的流程，可以复现这些重复；但这属于根据截图建立的可能输入，不能当成对该服务器的实测日志。

## V9 的具体处理

| 问题 | 处理 | 实际边界 |
| --- | --- | --- |
| P7 组合与通用组合同时出现 | 合并所有 Profile 组合；独立 DV 仍可细分 Profile | 组合不再显示 P5/P7/P8 编号 |
| 孤立字段重新触发单项 | 正式配置要求同一候选包含视频分辨率或编码，以及音频格式 | 字段不完整时会漏显；有宽松版可回退 |
| 同文本多个等级叠加 | 增加组合和各分类的优先级排除 | 无法撤销另一个候选已经产生的命中 |
| 完整组合排在后面 | 组合放到数组前部，调整标准分组顺序 | 客户端自行排序时仍由客户端决定 |
| EPX 浅色界面白字不清晰 | 原中心 alpha 为 1/255，改为不透明深色圆角底 | 客户端整体调低图片透明度仍可能影响显示 |
| 复杂版浅色边缘偏亮 | 保留不透明深色渐变，补充深色外轮廓 | 原复杂版中心已不透明，不能把它的所有浅色异常归因于透底 |
| DV + Atmos 中文 | 统一“杜比视界+全景声”，编码并入第一行 | 320×96 画布不变，长标题按可用宽度排版 |

## 已通过的字段集合测试

以下均为人工构造的非敏感测试数据，没有保存用户截图或服务器名称到仓库。

1. 独立字段 `2160p HEVC`、`REMUX`、`UHD Blu-ray`、`DV P7`、`TrueHD Atmos`、`7.1`，再加合并字符串：正式规则只保留 DV+Atmos+TrueHD、4K、REMUX、HEVC、7.1。
2. 完整文件名已经含 DV+Atmos+TrueHD，Profile 在另一字段：不再产生 Profile 组合与通用组合的重复。
3. 只有 `Dolby Vision`、`Atmos`、`TrueHD`，没有分辨率或视频编码：严格版不显示。这个漏显是明确的取舍，宽松版可显示。

## 保留的失败边界：两个候选都足够完整

候选一为 `Movie.2160p.BluRay.HEVC.HDR10.TrueHD.Atmos.7.1`，另一个字段为 `REMUX DV P7`，客户端还会把二者拼接。

候选一能触发 Atmos+TrueHD、UHD Blu-ray、HDR10；拼接后的候选能触发 DV+Atmos+TrueHD、REMUX。若客户端取并集，这些结果仍会同时存在。严格条件不能判断“别的候选更完整”，因此不能承诺仅改 JSON 即彻底解决。

已核对的公开实现：[NuvioTV StreamBadgeRules.kt](https://github.com/NuvioMedia/NuvioTV/blob/c8dcd453269a9306fe0e25c52813a9f456373a31/app/src/main/java/com/nuvio/tv/core/streams/StreamBadgeRules.kt)。其中 `badgeMatchCandidates` 保留原字段及拼接候选，任一候选命中即可加入最终结果。EplayerX 和 CapyPlayer 未取得对应匹配器源码，不能据此断言它们内部代码完全相同。

从集合行为也能理解这一点：客户端不断把新的命中加入结果；某条正则没有接口删除另一条已匹配的徽章。随意增加未经支持的 `exclusive`、`priority`、`replaces` JSON 属性并不会让客户端实现删除。

`tools/select_badges.py` 给出客户端汇总后的真实选择逻辑：最高组合优先、音频只保留一个选择、DV 覆盖低级 HDR、每个其他分类只保留优先项。上述反例经过该选择器会只保留 DV+Atmos+TrueHD、4K、REMUX、HEVC、7.1。它没有被 EplayerX / CapyPlayer 自动加载，必须由客户端开发者集成。

## 浅色模式验证

全部 133 张 PNG 的文字区域 alpha 均为 255。分别合成到浅色与深色背景后，该区域像素完全一致；圆角外侧仍透明。EPX 的白字透底问题在资源层已消除。复杂版原本已有不透明中心，因此若新 PNG 仍整体发白，应继续检查客户端的透明度、图片着色和当前是否显示缓存旧图。

`previews/Themes-v9.png` 是同一图片叠放在深浅背景的设计预览，不是软件运行截图。

## 更新与后续实机判断

先移除或替换旧徽章包，再导入 EPX9 或 all9，避免遗留的 V8 Profile 组合继续参与匹配。信息不足时可换同风格的 Relaxed 版本；同一时间只启用一套。
