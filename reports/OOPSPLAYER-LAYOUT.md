# OopsPlayer BF1：间距排查与客户端调整建议

2026-10-05

## 当前状态

用户已经重新导入 BF1。同一示例现在实际显示良友4K、UHD REMUX＋TrueHD、DV＋Atmos、7.1、HEVC 五枚徽章，另有播放器自带 MKV。识别修复已得到这份实机预览确认。

剩余问题是视觉布局：五枚横向徽章排成三行，图案之间存在明显宽空隙。详情页也有类似空隙，并可见 DD+ 显示尺寸与其他徽章不完全一致。这里不代表所有媒体、所有徽章都已通过实机验证。

## 已排除的原因

实际读取 GitHub PNG，检查透明通道，三个代表性良友图片都几乎铺满画布：

| 图片 | PNG 尺寸 | Alpha ≥32 的图案边界（左、上、右、下） |
| --- | --- | --- |
| 良友4K | 960×288 | 2、2、958、286 |
| 良友 DD+ | 960×288 | 2、2、958、286 |
| 良友 UHD REMUX＋TrueHD（诊断图使用的图片） | 960×288 | 2、2、958、286 |
| 默认 4K | 272×320 | 0、64、267、256 |
| 默认 Remux | 1200×320 | 0、32、1165、288 |

良友三张图片左右合计只有约 4 像素的低透明度边缘。就算裁掉全部这些边缘，也不可能消除截图中接近一整枚徽章宽度的空隙。已检查 DPI 的良友4K、DD+ 也与默认素材同在约 288 DPI，不能据此认定降低导出分辨率会解决间距。

这些是抽样测量，不是全部 161 张图片的逐一检查。源文件路径、Git blob 与原文件哈希见 [测量记录](oopsplayer-layout-observations.json)。没有上传用户截图。

## 占位框已有实机证据

前一轮 Diagnostic 使用了 `filled and bordered` 样式，为强制加载的 UHD REMUX 图片显示了青色外框。截图中外框约 215 像素宽，里面的实际图案约 104 像素宽。BF1 隐藏外框后，宽占位依然存在，所以视觉上表现为空隙。

这也说明，仅将 BF1 的 `filled` 改成默认预设的 `filled and bordered`，不能作为已经验证的间距修复；这种带边框样式此前就出现了同样的宽占位。

以上宽度来自缩放后的截图，是近似截图像素，不是 iOS 布局点数。它能证明外框明显宽于可见图案，不能确定播放器内部是哪一行代码造成的。需要检查图片视图、外层标签和换行布局的宽度计算是否一致。

默认预设的素材形状不同：例如默认 4K 画布接近竖方形，而截图中的良友徽章都是横向卡片。因此，不能仅用默认预设一行放几枚来推导良友应放几枚。图二和图四还是不同影片；同一个预览文件名的对比更有参考价值。

## 配置边界

检查了现有 JSON 与 BetterFormatter 公开生成器：已看到的相关字段是 `imageURL`、`tagStyle`、`tagColor`、`borderColor`、`textColor` 和分组信息，没有找到已确认可由 OopsPlayer 使用的图片宽高、内边距、列间距或行距字段。

这不证明 OopsPlayer 没有私有扩展字段，但在得到开发者的字段说明之前，往 JSON 里随意加入 `spacing`、`imageWidth` 或 `padding` 不能算有效修复。当前没有 OopsPlayer 的标签布局源码或设备布局调试器，不能直接修改它的视图布局。

参考来源：[BetterFormatter 导出生成器](https://github.com/9mousaa/BetterFormatter/blob/34591035590d1aed4cf564c145056b0aa864ebd3/src/fusion.mjs)。网页预览的 CSS 属于配置网站，修改它不会修改 OopsPlayer 原生界面。

## 给播放器开发者的具体调整建议

1. **让换行布局使用图片实际显示宽度。** 图片宽度可由“实际显示高度 × 原图宽高比”计算；图片控件、外层标签和布局测量应使用同一组尺寸。如果设置最大宽度，应等比调整高度，而不是只缩小图案、留下旧的宽外框。
2. **检查标签额外占宽。** 特别检查外层固定宽度、最小宽度、隐藏文字占位、重复内边距、单枚标签上的伸展布局，以及异步图片加载后是否仍使用加载前的估算宽度。这里只列排查点，不代表已确认应用使用了这些实现。
3. **统一实际图片高度与行间距。** 先保留现在可读的图片高度，横向间距可从 4–6 pt、纵向间距从 4–6 pt 起调；这些是建议值。整体标签行可以居中，单枚图片不应各自占据一个明显宽于图案的格子。
4. **同时检查设置预览、详情页和剧集卡片。** 同一素材在这三个位置应使用一致的宽高计算方式，再按页面需要等比缩放。

示意计算（不是对 OopsPlayer 已取得源码的补丁）：

```text
ratio = imageWidth / imageHeight
displayWidth = displayHeight × ratio
itemWidth = displayWidth + leftPadding + rightPadding
```

验证时使用当前 BF1、同一个预览文件名和原图片地址；先临时画出标签边框，确认边框贴合图案，再去掉调试边框。还应检查初次加载和图片缓存命中时是否一致。
