# OopsPlayer BF2：WEB-DL 组合后重复单项

2026-10-08

## 观察与复现

用户播放页截图同时显示「良友4K / WEB-DL」和独立「WEB-DL」。截图还包含 DV+Atmos、5.1、HEVC、Disney+。没有取得播放器的实际匹配输入，因此不把下面的候选字段模拟当作实机抓包。

原 all12 与 BF1 在单条完整输入 `2160p WEB-DL DV DDP5.1 HEVC DSNP English audio` 上均只产生 WEB-DL 组合，不产生单项。但是如果客户端再匹配独立的 `WEB-DL` 字段，然后把两次结果合并，独立 WEB-DL 就会被加回来。完整隐藏标记与孤立 Web 标记也存在相同问题。只在同一条正则里排除 4K／1080P 不能撤销另一条输入已经命中的单项。

## 本次调整

只调整 OopsPlayer 的 `ly12-web-dl` 逻辑徽章：**单独显示 WEB-DL 时，同一条匹配输入必须具有可识别的分辨率**。所有组合条件、其余 160 枚徽章的规则、原图、名称、颜色和相对顺序保留。`all12.json` 及其他播放器配置不修改。

| 输入情况 | BF2 行为 |
| --- | --- |
| 4K／1080P ＋ WEB-DL | 显示原来的分辨率＋WEB-DL 组合 |
| WEB-DL ＋ AAC／DD+ 等已有音频组合 | 保留原组合 |
| 上述完整输入，再附加孤立 WEB-DL／来源字段／Web 标记 | 不再额外增加独立 WEB-DL |
| 720P／576P／480P ＋ WEB-DL，未合入来源组合 | 保留独立 WEB-DL |
| 有分辨率的 REMUX ＋ WEB-DL | 按原规则保留可共存的独立来源信息 |
| 只有 WEB-DL，没有分辨率 | 不显示独立 WEB-DL；这是此次适配的明确取舍 |

无分辨率时，已有 WEB-DL＋音频组合仍能显示；但 `WEB-DL TrueHD` 这种原本需要两个单项、又没有分辨率的输入只保留 TrueHD。不能把这种差异描述成完全无损或与 all12 完全等价。

为了保持每条正则 ≤4096，WEB-DL 使用三个互斥入口：普通文本（无 REMUX）、含 REMUX 的文本、七位隐藏标记。普通文本入口都排除隐藏标记，含／不含 REMUX 的文本入口互斥；同一输入不会因拆分重复命中同一枚徽章。

## 验证

- 原有 7,447 组有序对照全部通过；67 组文本、104 组标记按新策略移除了无分辨率的 WEB-DL 单项，其余结果与原版一致，非预期差异为 0。
- 新增 473 项专项断言，覆盖 7 种完整输入与 10 种独立来源候选取并集、分辨率与音频组合、低分辨率单项、标记顺序、CRLF 及其他换行符。
- 检查三份 OopsPlayer 发布入口内容完全一致、161 枚逻辑徽章的元数据与排序、每条正则的字符／UTF-16／UTF-8 长度，以及原 all12 哈希。
- 当前 166 条物理过滤项；最长 3,963 字符、4,095 UTF-8 字节。

[完整回归报告](oopsplayer-validation.json) · [专项报告](oopsplayer-webdl-validation.json)

本地测试验证了上述候选字段重复机制的处理；BF2 仍需用户重新导入后在相同片源实测。无状态 JSON 不能处理所有跨字段冲突，例如两条独立输入分别声明 4K 和 720P、或互相矛盾的音频格式。要在保留一切低信息回退的同时实现全局互斥，需要播放器合并事实后统一匹配，或在结果合并后按组合成员去重。
