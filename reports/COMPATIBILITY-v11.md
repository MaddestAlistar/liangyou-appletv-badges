# V11 兼容性复盘

2026-09-25；基线提交 `42a0ad01f667a50130661c87a8ee8d0d2804bf1b`。

## 发现的问题

1. 复杂版 V10 的 155 条规则中，128 条含 `\A`／`\Z`。Python／ICU 接受这些锚点，ECMAScript 不具有同样语义。把既有 `(?i)` 前缀转成 `i` 标志后，Node 中 `4K`、`HEVC`、`WEB-DL`、`BluRay Remux` 都未命中，HDR／SDR 的旧规则仍可命中。此前仅测试 Python 和 ICU，未捕获这个兼容问题。
2. 一些完整正则被多次嵌套，最长 76,292 字符。V11 用共享布尔条件编译、线性优先级判断及普通 `^`／`$`，最长 4,927 字符，不包含旧锚点。
3. EplayerX 主地址仍为历史严格上下文版本；`EPX10.themefix` 才是此前的修复版本。V11 从修复图形配置出发，统一主地址与兼容入口。
4. 规则审查发现高规格视频标签被用来推断 DTS-HD MA，解码采样格式被用来推断 PCM，以及弱 TrueHD 线索被用来推断 Atmos。V11 移除这些推断。按用户要求保留 DV + DD+ 5.1／7.1 的 Atmos 兼容启发式。
5. 旧 `WEB` 回退会吞掉 `WEB-Rip`；PCM 编码 ID `pcm_bluray` 会误触发蓝光来源；紧凑声道写法可能把 `channels=20` 当作 2.0。均已添加独立反例并修复。

这是一组已复现的配置问题，不是对截图中播放器内部实现的断言。截图显示的 5.1 与 Node 模拟并非完全相同；未获得客户端原始候选文本、导入器源码或设备运行日志，不能确认该设备实际采用哪种引擎，也不能将所有缺失都归为单一原因。

## 统一范围

复杂版 `all`／`all9`／`all10`／`all11`／`all.Relaxed` 逐字节一致；EplayerX `EPX`／`EPX9`／`EPX10.themefix`／`EPX11`／`EPX.Relaxed` 逐字节一致。单项复杂版与 EplayerX PNG 由同一构建器生成。公共事实与排除规则同步，EplayerX 仍保留 41 个精简图形，复杂版为 155 个候选。

REMUX 所在 `master-source` 单独排序。EplayerX 的 REMUX 与 UHD Blu-ray 可各显示一枚；复杂版将 UHD + REMUX（及适用音频）合为同一枚 master 徽章，其图形明确表达两个来源属性，无需重复普通 UHD Blu-ray。泛 REMUX 与普通 Blu-ray 来源可共存。

同一候选中，来源、音频、分辨率、画面格式、声道、编码、位深各按既定优先级选择。Atmos 是附加音频属性；TrueHD 可以继续作为片源组合的一部分或独立单项。DD+ 在 Atmos 命中时让位，其对应来源通过单项回退保留。

平台缩写仍用于 WEB-DL 回退；明确 WEBRip 不会被缩写覆盖。显式 WEB-DL 与 WEBRip 冲突时，优先显式 WEB-DL。`Mad Max` 中的 Max 不作为平台或来源线索。

## 可复查的验证

运行 `python tools/test_portable_badges.py`。测试直接读取全部实际交付 JSON，并与生成器输出及每个别名对比，不只测试内存里的条件。

- 322 个固定场景、4 个配置变体、3 个引擎，3,864 次完整命中集合对比。
- Node 验证先把协议中的 `(?i)` 前缀转换为 `i` 标志，验证其后模式的 ECMAScript 语义；这不等同于实现某款播放器的导入器。
- 覆盖截图可见的低信息来源、单独 4K／HEVC／5.1、全部 55 种来源音频组合及无组合回退、DD+／Atmos 边界、dca profiles、PCM IDs、声道误判、字幕排除，以及音轨语言集合。
- 完整文件名与合并播放字段获得同样顺序的 6 枚复杂版徽章，声道位于编码之前，良友 4K 第一。
- 每个引用图片都存在；PNG 解码为 RGBA 960×288；SVG 为 320×96 且没有未转轮廓的文字。新增 41 张 EplayerX PNG 使用既有修复版 SVG 渲染。
- 对长噪声文本测量 ICU 与 Node 的匹配耗时；具体结果见 [机器报告](portable-validation-v11.json)。

## 保留的限制

没有依赖未经确认的客户端字段，例如跨候选优先级脚本或动态组合 API。跨字段取并集仍可能出现组合加单项；测试包含此真实反例。播放器不提供元数据时，配置不能凭文件大小、码率或截图标签恢复它；播放页排序与数量上限也由客户端决定。

本次保留 Main10／DV／UHD 蓝光／4K REMUX 到 HEVC 的回退，但显式 AV1／AVC 等冲突编码会阻止该推断。保留的 Atmos 与来源缩写回退均已在 README 标明是兼容策略，不作为媒体或硬件能力认证。未进行私人服务器或客户端设备测试。
