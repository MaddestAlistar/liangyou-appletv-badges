## 可以修复与需要客户端配合的部分

| 层面 | 已做处理 / 已查证事实 | 边界 |
| --- | --- | --- |
| 规则 | 修正重复 ID、格式混淆、标签边界、多行输入；加入组合与同文本排除条件 | 规则看不到本次输入之外的字段 |

## 组合为什么不能对所有客户端作统一保证

核对的 NuvioTV 源码版本：`c8dcd453269a9306fe0e25c52813a9f456373a31`。

- [StreamBadgeRules.kt](https://github.com/NuvioMedia/NuvioTV/blob/c8dcd453269a9306fe0e25c52813a9f456373a31/app/src/main/java/com/nuvio/tv/core/streams/StreamBadgeRules.kt)：`badgeMatchCandidates` 收集 filename、title、description、parsed audio / hdr 等独立字段，同时加入所有字段拼接后的候选文本；`matchesAnyCandidateReusable` 任一候选匹配即成功；`matchedBadges` 汇总结果。
- 同文件的去重依据是图片 URL 或名称，不是声明「组合覆盖哪些单项」。把组合排在前面，或让多个徽章使用相同 groupId，不能据此推导后续徽章一定被跳过。
- [StreamBadgeChips.kt](https://github.com/NuvioMedia/NuvioTV/blob/c8dcd453269a9306fe0e25c52813a9f456373a31/app/src/main/java/com/nuvio/tv/ui/components/StreamBadgeChips.kt)：图片高度、宽度范围和 Fit 缩放在客户端 UI 中控制，配置本身没有可据此使用的统一卡片高度属性。

可复现场景：字段分别为 `DV`、`Atmos`、`TrueHD`，客户端额外拼接出 `DV Atmos TrueHD`。组合匹配拼接文本；三个单项仍能分别匹配独立字段。最终结果是组合和三个单项同时存在。测试记录明确保留此结果，不把它写成通过全局互斥。

若修改客户端，要实现可靠互斥，应先针对同一个 MediaSource 整理规范化信息，或在汇总命中后根据组合的构成删除被覆盖的单项。规则配置中随意添加 `exclusive`、`priority`、`replaces` 等未经客户端支持的字段不能实现这一步。本次未修改任何客户端软件。

EplayerX 的公开参考格式使用标准分组，可见 [6otho/Epx-Badge](https://github.com/6otho/Epx-Badge)。这只能作为格式参考；未取得 EplayerX 自身 matcher 源码，也没有该设备的运行日志。因此不能把 Nuvio 的具体行为直接认定为 EplayerX 的行为。

## 如何定位仍然存在的大小或内容差异

1. 更新正式配置，确认只启用一份。若仍显示旧配色，改用 EPX8 / all8 新地址。不要将两个完整版本一起导入到同一规则列表。
2. 临时只使用尺寸诊断配置。它无条件请求同一张 SIZE TEST 图。若不同服务器资料卡中的这张图仍有不同尺寸，说明差异不来自各枚徽章自身的画布，需要继续核对客户端布局、缓存和卡片模板。诊断图完全不出现时，应先检查配置导入、图片网络请求及客户端是否执行规则。
3. 将 EPX SVG 版换成 EPX PNG 版比较。规则完全一样，图片格式不同；只有其中一种异常，可缩小到解码或渲染路径。PNG 不承诺绕过客户端对整行徽章的缩放。
4. 比较资料卡与播放页时，使用同一片名下的同一个媒体版本 / MediaSource，并记录当前音轨；不要把不同版本的资源结果当作同一输入比较。
5. 若仍有差异，提供两张对应截图、客户端版本、JSON 地址，以及脱敏后的媒体名称 / 显示标题 / codec / HDR / 音频 / 声道字段。只有获得实际输入，才能判断是缺字段、匹配错误还是界面截断。

## 数据含义与保守识别

- 徽章描述输入标签，不代表设备实际解码、电视输出或当前音轨。转码可能改变实际播放格式。
- 不将未标 HDR 当成 SDR；不从 Main10 单独推断 HEVC；不从音轨数量推断声道布局。
- 4K Blu-ray 编码可显示 UHD Blu-ray 片源；若明确 REMUX，则优先显示 REMUX。徽章不证明文件是完整 ISO / BDMV 原盘。
- 一段文本含多个分辨率或声道时，本配置按优先级压缩显示；这不是识别当前选中版本或音轨的证据。
- 平台缩写须有 WEB 上下文或明确平台字段；避免用裸 MAX / CR 误认电影名。版本标识仍依赖源字符串准确，电影标题本身与标签同名时需要上游提供结构化字段。
- Dolby Vision Profile 只根据明确标识识别；不能从 WEB / REMUX 或分辨率推断。冲突 Profile 回退到通用 DV。
- 组合中的 TrueHD / DD+ 与 Atmos 是同输入共现关系，多音轨描述可能无法确定其关联。要表达「当前音轨采用哪种 Atmos 编码」，需播放器传递对应的单轨信息。

## 本次验证范围

474 个输入场景，每个分别在 Python re、ICU 74 和 Java 17 Pattern 执行；共 1,422 次结果断言。覆盖组合标签顺序、多行、DV Profile、HDR10+、紧连声道编码、视频 Level 误判、来源 / 平台 / 字幕误触发等。

10,000 字符无标签长文本经过全部规则的 ICU 匹配约 0.15 秒（本次环境记录，非手机或 Apple TV 性能承诺）。全部 145 份 SVG 与 145 份 PNG 检查尺寸、依赖和本地资源引用。完整预览已人工目视检查。

未进行 Apple TV、iPhone 或各播放器的实机测试；未获取用户不同服务器的真实 MediaSource 输入。V8 修复了配置和资源内可验证的问题，并保留了客户端行为的明确边界。
